# Инвест-пул — React/Vite

Отдельный кабинет для [Go REST API invest-pool-go](https://github.com/phosphoriat/invest-pool-go).
React-компоненты реализуют сценарии региона, технолога, эксперта и инвестора.
Доли, ограничения, права и начисления проверяет Go-сервис; клиент не вычисляет выплаты.

## Локальный запуск

Нужны Node.js 22.12+ (рекомендуется 24+), npm и работающий Go-сервис на порту 8080.

Терминал 1 — бэкенд:

```sh
git clone https://github.com/phosphoriat/invest-pool-go.git
cd invest-pool-go
go run ./cmd
```

Терминал 2 — клиент:

```sh
git clone https://github.com/phosphoriat/invest-pool-react.git
cd invest-pool-react
npm ci
npm run dev
```

Открыть **http://localhost:5173**. Vite проксирует `/api/*` на `http://127.0.0.1:8080`, сохраняя путь. Другой адрес
задаётся серверной переменной `API_TARGET` в `.env` (см. `.env.example`) или перед запуском:
`API_TARGET=http://localhost:8081 npm run dev`. Перезапустить Vite после изменения настройки. Секреты в клиентскую
сборку не передаются.

## Docker: два независимых репозитория

Сначала запустить backend с именем Compose-проекта `invest-pool`:

```sh
# Из каталога invest-pool-go
docker compose -p invest-pool up --build -d --wait
```

Затем из этого репозитория:

```sh
docker compose up --build -d --wait
```

Кабинет — **http://localhost:5173**. Nginx обслуживает собранный `dist` и проксирует `/api/*` на `http://app:8080` по
внешней сети `invest-pool_default`. Backend не собирается и не копируется в образ клиента. Если у backend другое имя
Compose-проекта, указать существующую сеть: `BACKEND_NETWORK=my-project_default docker compose up --build -d --wait`.

Для самостоятельного развёртывания образа переменная `API_UPSTREAM` задаёт доступный из контейнера адрес API без
завершающего `/`, например `http://backend:8080`. Nginx передаёт `X-User-Id` и `X-Role` без подмены. В браузере запросы
остаются same-origin, CORS на Go не требуется. При раздельных публичных доменах следует настроить reverse proxy на
домене клиента; прямые cross-origin запросы здесь не включены.

Остановка клиента: `docker compose down`. Остановка backend выполняется отдельно из его репозитория. Данные SQLite
принадлежат backend.

## Работа кабинета

1. **Томская область · region**: опубликовать «Томская область, очистка воды».
2. **Технолог очистки воды · technologist**: предложить решение.
3. **Эксперт · expert**: подтвердить матч.
4. **Томская область · region**: создать пул `1000000`.
5. **Инвестор A · investor**: внести `600000`.
6. **Инвестор B · investor**: внести `400000`.
7. **Томская область · region**: зафиксировать прибыль `100000`. Появятся начисления `60000` и `40000`.
8. Нажать «Повторить ту же операцию»: та же прибыль отправляется ещё раз, начисления не удваиваются.
9. Под A/B в «Моих инвестициях» проверить собственные выплаты. Эксперт и регион могут открыть журнал событий и обновить
   его после доставки outbox.

Все суммы — целые минорные единицы, максимум `9000000000000000`. Ключ операции нужен только вкладу: распределение одно на
пул, и повтор той же прибыли API сам считает идемпотентным. Ключ вклада сохраняется в `sessionStorage`
до подтверждённого успеха, чтобы повторить запрос после сетевой ошибки или перезагрузки вкладки. Если хранилище браузера
отключено, ключ хранится только в памяти; сохраните его перед перезагрузкой. При неизвестном результате повторяйте **тот
же ключ и сумму**. После подтверждения UI создаёт новый ключ для следующего вклада. Создание проблемы/решения не
идемпотентно по контракту API.

UI показывает только доступные роли действия. Источник пользователей, проектов и начислений — API, а не локальные сиды.
При смене пользователя кабинет размонтируется, незавершённые запросы чтения отменяются; ответы прежней роли не
отображаются. Команды уже отправленного пользователя могут завершиться на сервере. Ошибки API показываются в интерфейсе.
Авторизация заголовками — демонстрационная.

## Сборка и проверки

```sh
npm run build
npm test
npm run format:check
```

Проверка React → Vite proxy → Go API (backend-репозиторий рядом, Go 1.26+):

```sh
(cd ../invest-pool-go && go build -o bin/invest-pool ./cmd)
npm run test:live
```

Другой путь к бинарнику: `GO_BACKEND_BINARY=/absolute/path/invest-pool npm run test:live`.

Live-тест сам запускает изолированную SQLite/Go на `127.0.0.1:18089` и Vite на `127.0.0.1:18090`, выполняет сценарий в
React DOM, проверяет идемпотентность, приватность и аудит, затем завершает свои процессы. Эти порты должны быть
свободны. Vitest использует jsdom: это проверка поведения компонентов и реального REST-взаимодействия, не визуальный
браузерный тест. CI также собирает оба Docker-образа и проверяет Nginx-прокси.

`npm run preview` локально показывает production build на http://localhost:4173 с тем же API_TARGET.
Для production используйте Nginx, а не Vite preview.

## Структура

| Путь                          | Назначение                                    |
|-------------------------------|-----------------------------------------------|
| `src/App.jsx`                 | Выбор пользователя и ролевой кабинет          |
| `src/api/client.js`           | REST, auth-заголовки и ошибки                 |
| `src/hooks/useCabinet.js`     | Загрузка, команды и отмена устаревших ответов |
| `src/components`              | Формы, карточки проектов, аудит               |
| `src/styles.css`              | Стили                                         |
| `tests`                       | API-клиент, формы, смена ролей, live-сценарий |
| `nginx/default.conf.template` | Production static hosting и REST proxy        |

REST: GET `/api/users`, `/api/state`, `/api/events`; POST `/api/problems`, `/api/problems/:id/solutions`, `/match`,
`/pool`, `/investments`, `/profit`. Команды отправляют только поля операции: `text`, `solution_id`, `amount`, `key` (только у вклада).
Полный контракт и матрица прав — в README backend.
